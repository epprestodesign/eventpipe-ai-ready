## Token architecture for designers

The system uses **three token layers**. Designers work at the **semantic** layer — meaningful names like `brand.primary` and `text.secondary` rather than hex values.

```
Primitive tokens    →   Raw values (#0057FF, 14px, 600)
       ↓
Semantic tokens     →   Named decisions (color.brand.primary, typography.body2.fontSize)
       ↓
Component tokens    →   Component-scoped (button.contained.primary.background)
```

**In practice for designers:** Reference semantic tokens when specifying colors in designs. Component tokens are managed by engineering and derive from semantic choices.

## Color system

The color palette is split into:

- **Brand** — primary (#0057FF blue), secondary (#8B5CF6 purple)
- **Status** — error, warning, success, info
- **Text** — primary, secondary, disabled, onBrand
- **Background** — default (#F9FAFB), paper (#FFFFFF)
- **Action** — hover, focus, selected, disabled overlays
- **Neutral** — lighter → darker grayscale scale

See **Foundations → Color** for the full palette.

---

## Typography system

The type scale is based on the Inter font family with variants: `h4`, `h5`, `h6`, `subtitle1`, `subtitle2`, `body1`, `body2`, `caption`, `overline`, `button`.

See **Foundations → Typography** for the full scale with sizes and weights.

---

## Spacing

Based on a **4px grid**. Common multiples: 4, 8, 12, 16, 20, 24, 32, 40, 48px.

Component padding, gaps, and margins always use multiples of 4px, defined as tokens.
