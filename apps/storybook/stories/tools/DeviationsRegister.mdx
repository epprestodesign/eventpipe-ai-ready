# Deviations register

When a component must deviate from the standard build workflow, it is documented here. Deviations are reviewed and approved before merging.

> Source of truth: `docs/contracts/component-build-workflow.md` — Deviations register section.

---

## What counts as a deviation?

A deviation is any intentional departure from the rules in the component build workflow:

- Reading `--ep-semantic-*` or `--ep-primitive-*` vars directly (token layer isolation)
- Using `@mui/icons-material` directly (icon system)
- Skipping a required story (Storybook coverage)
- Non-standard prop forwarding or typing patterns

Deviations are **not** tracked for:
- Framework resets (overriding MUI internal slot geometry)
- Graduated system rules (patterns that have been formally adopted)

## How to register a new deviation

1. Implement the deviation with a code comment explaining why
2. Add an entry to `docs/contracts/component-build-workflow.md` — Deviations register section
3. Update this page with the same entry
4. Get approval in code review before merging
