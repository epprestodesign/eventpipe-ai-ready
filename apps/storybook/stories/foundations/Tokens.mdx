# Tokens

The EventPipe token system uses three distinct layers. Each layer has a clear responsibility, and the layers communicate only in one direction: downward.

---

## Data flow

```
packages/tokens/src/primitive/     →  Raw values (hex, px, numbers)
packages/tokens/src/semantic/      →  Aliases to primitives
packages/tokens/src/component/     →  Component-scoped aliases to semantic

         pnpm --filter @eventpipe/tokens build

packages/tokens/dist/tokens.light.css   →  All CSS custom properties (light theme)
packages/tokens/dist/tokens.dark.css    →  Dark overrides only
packages/tokens/dist/tokens.css         →  Light + dark combined (import this)
```

---

## TOKEN helper map pattern

Every component defines a `TOKEN` const at the top of its implementation file. This is the only place where CSS var strings are written — they are never scattered inline.

```tsx
const TOKEN = {
  background:   () => `var(--ep-component-button-contained-primary-background)`,
  color:        () => `var(--ep-component-button-contained-primary-text)`,
  borderRadius: () => `var(--ep-component-button-border-radius)`,
  focusColor:   () => `var(--ep-component-button-focus-ring-color)`,
  focusWidth:   () => `var(--ep-component-button-focus-ring-width)`,
  focusOffset:  () => `var(--ep-component-button-focus-ring-offset)`,
} as const;
```

Advantages: token names are in one place, easy to audit, and TypeScript-safe.

---

## Adding a new token

1. Add the value to the appropriate JSON file in `packages/tokens/src/component/`
2. Reference only `{semantic.*}` — never `{primitive.*}` — from component tokens
3. Run `pnpm --filter @eventpipe/tokens build`
4. Use the new CSS var in the component via `TOKEN`

The build validator (`ep/validate-component-refs`) will fail if a component token references a primitive directly.
