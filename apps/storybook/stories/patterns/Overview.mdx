# Patterns

Patterns are recurring UI solutions composed from EventPipe components. They represent the recommended approach for common product scenarios — not prescriptive templates, but proven compositions with documented rationale.

## Principles for composing patterns

1. **Use components as-is.** Patterns are compositions of existing components — they don't require modifying component internals.
2. **Token-only customization.** Adjustments to spacing, color, or size within a pattern must be made through tokens or `sx` props — never inline hardcoded values.
3. **Accessibility carries through.** Each component in a pattern maintains its own accessibility contract. The pattern author is responsible for ensuring composition-level semantics (e.g., `aria-labelledby` on a Dialog inside a pattern).
4. **Patterns are documented, not enforced.** Teams may deviate from patterns for valid product reasons, but deviations should be documented.
